How comparable this is

Same test, same restart, same code

Phantom's Sedov setup in its default periodic box, npartx = 100 close-packed: 1,368,000 particles, the third point of the paper's Fig. 17. As in the paper, the setup is evolved five steps (both CFL factors 10⁻³) to make the restart; it was made once on the CPU and every platform starts from it. PERIODIC=yes IND_TIMESTEPS=no, no corrector sub-cycling, I/O excluded. One source export, built with the same flags everywhere.

A100 is the PCIe card

Shamrock ran on an A100-SXM4-40GB in a DGX (NVLink host link). Ours is an A100-PCIe-40GB in mad05 (EPYC 7702 host), with host↔device transfers over PCIe: 14 ms of the 99 ms step. mad06's A100 was shared with other jobs; on mad05 the other cores were running unrelated single-threaded jobs, so ours were bound to 16 idle cores beside the GPU.

CPU generations

The paper's Phantom CPU figure is a 64-core Zen 2 Epyc 7742 (2019). Our EPYC 9745 is a current Zen 5c socket run on all 120 cores; on 64 of them it gives 3.94×10⁶ particles/s.

Timer fix used for these runs

Phantom's section timers step in 1/8 s mid-month: the start time is held in single precision as seconds since the start of the month. These runs keep it in double precision. The fix changes no physics.
