Orion timing pages

1M particle strong scaling: this code against main

The 1M Orion run, one maximum timestep, at two stages of the run, on one 128-core socket of mad11 (memory bound to that socket), one run at a time. Pure OpenMP: an OpenMP-only build, one process with N threads. Pure MPI: N ranks with one thread each. This code against sphNG main (bace503, June 2026: no domain checking and none of the thin-substep, RT or OpenMP changes), with the same build settings (RT with dust, iptdim 500, nummaxproc 128, ipartialrevtree 2, -O3), dumps and input file. MPI uses the SEND path in both codes; main also has a second MPI line with its default SENDRECV path. Each row of plots shares its y axis, so the two codes can be compared directly. Hover or focus a point for its values.

Everything on this page runs on a single socket of a single node: MPI messages pass through shared memory (Intel MPI with the shm provider), never the network fabric.

    Minutes: the “time used” of the maximum timestep (clONC log), which includes the first time around (the full evaluation of all particles at the start of the step). Efficiency = T(ref) × cores(ref) / (T × cores), with the 1-core run as reference when it has finished, otherwise the finished run with the fewest cores in each series.
